Colour palette

type anything; the model says which colours express it, and how much of each
type above to see its colours

The stripes are the model's probabilities for the question "which colour does this make you think of?". Every colour is described by what it looks like in real life ("red, the colour of tomatoes, fire trucks, roses, blood"): the description is what the model matches your text against, so a short list of described colours works far better than a long list of bare names. Language models read options as letters and favour the first ones, so for them the question is asked four times with the list rotated and the answers averaged. Small models are often right about which colours belong but unsure how much of each, so \"contrast\" sharpens the stripes (the order never changes). Requests are coalesced while you type, and only the newest answer is shown.

Framing and Criteria are unproven experiments, not defaults: for phrases with no literal colour (a brand, a place, "Ikea", "Brazil"), the described-option wording may anchor the model to object look-alikes rather than association, and the plain instructions never ask for association at all. Try both against a few such phrases and compare; nothing here claims one is better until you've seen it.
